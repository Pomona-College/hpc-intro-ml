## Contributing

This lesson is part of the **Pomona College HPC Workshop Series**, maintained by
the ITS Research Computing team. We welcome contributions of all kinds: fixes to
existing material, bug reports, new exercises, and reviews of proposed changes.

Issues and pull requests for this lesson belong [in this
repository][repo-issues] — not with The Carpentries, who do not maintain it.

### Contributor Agreement

By contributing, you agree that we may redistribute your work under [our
license](LICENSE.md). In exchange, we will address your issues and assess your
change proposal as promptly as we can. Everyone contributing to this lesson
agrees to abide by our [code of conduct](CODE_OF_CONDUCT.md).

### How to Contribute

The easiest way to get started is to file an issue to tell us about a spelling
mistake, some awkward wording, or a factual error.

1. If you do not have a [GitHub][github] account, you can [send us comments by
   email][contact]. We will be able to respond more quickly if you use one of
   the other methods described below.

2. If you have a [GitHub][github] account, or are willing to [create
   one][github-join], but do not know how to use Git, you can report problems
   or suggest improvements by [creating an issue][repo-issues].

3. If you are comfortable with Git and would like to add or change material,
   you can submit a pull request (PR). Instructions are [included
   below](#using-github).

Note: if you want to build the website locally, please refer to [The Workbench
documentation][template-doc].

### What to Contribute

There are many ways to contribute, from writing new exercises and improving
existing ones to updating or filling in documentation and submitting [bug
reports][repo-issues] about things that do not work, are not clear, or are
missing.

Corrections to Sagehen-specific details are especially welcome — cluster
configuration, module versions, partition names and storage paths change over
time, and the lesson needs to keep up.

Comments on issues and reviews of pull requests are just as welcome. **Reviews
from novices and newcomers are particularly valuable**: it is easy for people
who have been using this material for a while to forget how impenetrable some
of it can be, so fresh eyes are always welcome.

### What *Not* to Contribute

This lesson already contains more material than we can cover in a typical
workshop, so we are usually *not* looking for more concepts or tools to add. As
a rule, if you want to introduce a new idea, you must (a) estimate how long it
will take to teach and (b) explain what you would take out to make room for it.

### Using GitHub

If you choose to contribute via GitHub, you may want to look at [How to
Contribute to an Open Source Project on GitHub][how-contribute]. In brief, we
use [GitHub flow][github-flow] to manage changes:

1. Create a new branch in your desktop copy of this repository for each
   significant change.
2. Commit the change in that branch.
3. Push that branch to your fork of this repository on GitHub.
4. Submit a pull request from that branch to the [upstream repository][repo].
5. If you receive feedback, make changes on your desktop and push to your
   branch on GitHub: the pull request will update automatically.

NB: The published copy of the lesson is in the `main` branch.
